# Telegis — AI-гид по Астане

Гид по району EXPO / Mega Silk Way: реальные POI, факты с источниками, проверяемые рекомендации и **мини-маршрут с возвращением и запасом времени**. Данные OpenStreetMap, официальные сведения о местах и пешеходный граф собираются автоматически. В комплект входят интерфейс с картой и презентация.

Проверенный пример: Mega → Аллея мира и согласия → 25-ти летие Независимости → Drinkit → Mega, примерно 107 минут, включая 12 минут запаса. На 60 минут такой план не обещается. [Подключение фишки к интерфейсу](docs/itinerary-handoff.md), [полный ответ](docs/itinerary-example.json).

## Быстрый запуск

Python 3.11 или новее. Выполняйте команды из этой папки проекта.

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --no-access-log --no-use-colors
```

На macOS/Linux используйте `.venv/bin/python` вместо `.venv\Scripts\python.exe`.
Если окружение уже активировано: `uvicorn app.main:app --host 0.0.0.0 --port 8000 --no-access-log`.

В Windows можно использовать `.\scripts\start.ps1`: он подхватывает `.venv`, создаёт `.env` только при его отсутствии и объясняет занятый порт. Если политика PowerShell запрещает запуск скриптов, используйте команду Python выше. Ошибка `10048` означает, что порт уже занят: откройте `/docs` существующего сервера; для перечитывания `.env` остановите его через Ctrl+C в его терминале и запустите заново. Другой порт: `.\scripts\start.ps1 -Port 8001`.

- API для проверки: http://127.0.0.1:8000/docs
- Состояние и число POI: http://127.0.0.1:8000/api/health
- Происхождение данных и ограничения: http://127.0.0.1:8000/api/meta
- Интерфейс: http://127.0.0.1:8000/
- Слайды: http://127.0.0.1:8000/presentation/slides.html
- PDF презентации: http://127.0.0.1:8000/presentation/slides.pdf

Сохранённый реальный датасет уже включён. Без ключа модели выдача работает в явно обозначенном `fallback`, а не в режиме RAG.

`python preview_server.py` — вспомогательный запуск того же приложения на порту 8080. Он использует настоящий датасет, расчёт графа и те же проверки API. Для основной демонстрации используйте порт 8000, чтобы не запутаться между процессами.

## Подключение модели

Скопируйте `.env.example` в `.env`, если `.env` ещё нет. Заполните локально:

```dotenv
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_API_KEY=YOUR-KEY
LLM_MODEL=openai/gpt-5.6-terra
LLM_REASONING_EFFORT=none
LLM_TIMEOUT_SECONDS=30
LLM_MAX_TOKENS=1200
LLM_JSON_MODE=true
```

Выбран [OpenRouter / GPT-5.6 Terra](https://openrouter.ai/openai/gpt-5.6-terra) с `reasoning_effort=none` для короткого структурированного ответа. Реальные проверки обоих сценариев сохранены в [live-rag-walk.json](docs/live-rag-walk.json) и [live-rag-cafe.json](docs/live-rag-cafe.json). Доступность модели и оплаченного API зависит от аккаунта. Для прямого OpenAI замените URL на `https://api.openai.com/v1`, модель на `gpt-5.6-terra` и используйте ключ OpenAI.

`LLM_MAX_TOKENS=1200` ограничивает ответ: без ограничения OpenRouter может резервировать максимум модели и отклонить короткий запрос с HTTP 402. Приложение посылает `max_tokens` в OpenRouter и `max_completion_tokens` другим провайдерам. `LLM_REASONING_EFFORT` для несовместимой модели можно оставить пустым.

`LLM_BASE_URL` — базовый URL, без `/chat/completions`. Поддерживается Chat Completions, JSON-ответ и Bearer-ключ. Для другого совместимого провайдера замените URL и точный ID модели, а `LLM_REASONING_EFFORT` оставьте пустым, если параметр не поддерживается. Для локального сервера допускается HTTP на localhost. Некоторые провайдеры не поддерживают `response_format`: тогда установите `LLM_JSON_MODE=false`, валидация ответа всё равно выполняется. После изменения `.env` перезапустите сервер.

Успешный вызов `/api/recommend` возвращает `mode: "rag"`. `llm_configured: true` в health означает только наличие настроек. `llm_last_status` показывает результат последней попытки в текущем процессе: `not_checked`, `ok`, `authentication`, `credits`, `rate_limit`, `timeout` и другие безопасные коды без ключей и текста провайдера. Ошибка сети/ключа/формата возвращает полезный `fallback` и пояснение.

Проверка настроек и датасета без вызова модели: `python scripts/doctor.py`. Проверка непосредственно провайдера: `python scripts/doctor.py --live` (один платный запрос). Проверка всей цепочки через работающий сервер: `python scripts/check_live.py --require-rag`.

Ключ не должен попадать во фронтенд, репозиторий или архив. `.env` исключён через `.gitignore`. Размещайте демонстрацию локально; для публичного доступа нужны защита API и лимиты расходов.

## Сбор и обновление данных

```powershell
python scripts/refresh_data.py
```

Команда последовательно запускает три сборщика. Каждый источник публикуется атомарно независимо; при сбое сохраняет свой прежний снимок, общий скрипт сообщает частичное обновление. Для отдельного запуска: `collect_pois.py`, `collect_walk_network.py`, `enrich_pois.py` в `scripts/`.

POI-сборщик делает ограниченный GET-запрос Overpass и проверяет результат Pydantic-моделями: круг 3,5 км около EXPO. Категории: кафе, парки, сады, площадки, музеи, галереи, достопримечательности, смотровые, арт-объекты, памятники и торговые центры. Неименованные/частные/запрещённые объекты исключаются, близкие дубликаты объединяются. Подробные теги сохраняются для объяснений.

Сборщик сети сохраняет `data/walking/`: исходные дороги и узлы OSM, отфильтрованный пешеходный граф, SHA-256 и лицензия. Обогащение сохраняет `data/enrichment/`: 3 разрешённых первоисточника, проверяемые признаки страниц, привязка к конкретным POI, даты публикации/получения, SHA-256 страниц и короткие подтверждающие выдержки. Если проверка источника не прошла, новая версия не публикуется. Полные чужие HTML-страницы не распространяются.

В текущей версии 49 POI, 72 факта для 35 мест (6 из официальных источников), 30 829 узлов и 73 816 направленных связей сети. NU Park исключён из выдачи до подтверждения доступности: официальный источник описывает будущий проект. Историческая статья о японском саде не выдаётся за проверку сегодняшнего доступа.

Сборщик сохраняет полный исходный ответ в `data/snapshots/<id>/raw.json`, затем:

- `pois.json` — нормализованные записи с конкретными URL объектов;
- `locations.json` — стартовые точки из тех же данных;
- `manifest.json` — запрос, время сбора, время базы OSM, количество, SHA-256 исходного ответа и лицензия.

`data/current.json` переключается только после проверки целого снимка: SHA-256 исходного ответа, идентификаторов, ссылок, стартовых координат, категорий и счётчиков. При таймауте/ошибке публикации старые данные остаются рабочими. API подхватывает новый снимок без перезапуска. Обновление запускается командой; фонового расписания нет. Публичный Overpass может отвечать 502/таймаутом — повторите позже, не запускайте частые циклы.

Для воспроизводимой офлайн-пересборки из сохранённого исходного ответа:

```powershell
python scripts/collect_pois.py --reprocess-current
```

Это не свежая загрузка: исходное время сбора сохраняется. Блокировка `.collect.lock` предотвращает одновременный запуск сборщиков. После аварийного завершения удаляйте её только убедившись, что сборщик уже не запущен.

Сведения о POI могут быть неполными. Отсутствие свойства записывается как `null`, а не выдумывается. `rating` отсутствует в исходных данных и остаётся `null`. Дата сбора не равна дате проверки реальной работы места.

## Интерфейс и контракт API

Папки `static/` и `presentation/` уже включены. Основные файлы интерфейса: `index.html`, `styles.css`, `app.js`. Ресурсы доступны под `/static/`, слайды — под `/presentation/`. Вызовы `fetch('/api/...')` идут на тот же сервер. Node/npm для запуска не нужны.

API запускается и без этих папок. На `/` тогда будет сообщение о готовом сервере, `/docs` останется доступным. Добавление `static/` подхватывается без перезапуска.

`GET /api/pois` возвращает каталог `{ "pois": [...] }` из проверенного снимка. Помимо полей POI, записи содержат доказательства, предупреждения и `recommendable`. Исключённый из рекомендаций объект не должен выглядеть как предложение посетить его.

`POST /api/poi_ai_info` принимает только `{ "poi_id": "..." }` и возвращает `summary`, `tip`, `evidence`, `warnings`, `source_url`, `mode: "sourced"` и пометки источников. Сводка опирается на сохранённые факты, а занятие обозначается как идея. Неизвестный ID возвращает 404. Этот endpoint не вызывает платную модель.

Для `/api/recommend` и `/api/itinerary` нужны разные тела запроса. Поле `category` относится только к рекомендациям, `include_coffee` — только к маршруту. Общие поля: координаты, непустой запрос и целый бюджет времени.

### GET /api/locations

```json
{"locations":[{"id":"osm_way_499328514","name":"Mega Silk Way","lat":51.0890897,"lon":71.4073303}]}
```

Это пример одной реальной стартовой точки; полный ответ содержит и вторую. Координаты в интерфейсе всегда берите из API, не фиксируйте по примеру.

### POST /api/recommend

```json
{"query":"Хочу погулять","lat":51.0890897,"lon":71.4073303,"available_minutes":60,"category":"walk"}
```

`category`: `walk` / `cafe`. Время — целое от 10 до 180. `query` — непустая строка до 1000 символов. Координаты проверяются на допустимый диапазон. Неизвестные поля не принимаются.

Ответ: `mode`, `used_context`, `recommendations`, `message`. В карточке всегда:

```text
poi_id, name, lat, lon, category,
distance_m, distance_kind="straight_line",
walk_minutes_estimate, visit_minutes_estimate, total_minutes_estimate,
why, activity, opening_hours (string|null), source_url, collected_at, warnings[],
description, phone (string|null), website (string|null),
fact_source, activity_source="suggested_idea", evidence[], time_margin_minutes,
travel_basis, route_distance_m, return_route_distance_m, route_connector_m
```

Пустая выдача — HTTP 200 и `recommendations: []`; причина в `message`. Неверный ввод — 422 и `detail`. Нет датасета — 503 и `detail`. Ошибка модели не ломает интерфейс: HTTP 200, `mode: "fallback"`. `used_context` повторяет поля формы без исходного запроса и добавляет `effective_minutes`, `max_distance_m`, `required_features`, `excluded_categories`. Например, запрос «на 20 минут, не дальше 500 метров» при форме на 60 сужает фактический бюджет до 20 минут и 500 м. Интерфейс должен показывать эти фактические ограничения.

Точные схемы: `/openapi.json` или экспорт `docs/openapi.json`. Проверенный пример настоящего ответа: `docs/api-example.json`.

## Как выбираются места

1. Проверка зоны покрытия и поддерживаемых ограничений.
2. Жёсткий фильтр категории/подкатегории, исключений и подтверждённых свойств. Простые явные ограничения времени/расстояния в тексте сужают значения формы; ориентир «кофе возле музея» не заменяет нужную категорию.
3. Расстояние по формуле гаверсинусов, до 2,5 км от пользователя.
4. При доступной сети OSM считаются реальные связные пути туда и обратно; несвязные варианты исключаются. Для совместимости `walk_minutes_estimate = max(1, ceil(max(outward_m, return_m)/70)) + 2` — оценка по более длинному направлению с запасом на вход. `distance_m` остаётся по прямой, пути — в `route_distance_m` / `return_route_distance_m`. Без сети используется явно помеченная эвристика `max(1, ceil(distance_m * 1.3 / 70)) + 2`.
5. Фиксированная оценка посещения по категории: кафе 15 минут, парк 20, музей 40, арт-объект 10 и т.д.
6. `total_minutes_estimate = 2 * walk_minutes_estimate + visit_minutes_estimate`. Включает возвращение. Не поместившиеся варианты исключаются.
7. Ранжирование: 65% нормализованный BM25 по POI и фактам с источниками, 35% близость. Небольшой словарь русских/английских синонимов. Это лексический поиск, не семантические эмбеддинги.
8. Три лучших найденных записи передаются LLM вместе с рангом. Модель выбирает проверяемые причины и занятие из разрешённого списка. Сервер сохраняет порядок релевантности, требует присутствия первого кандидата, проверяет все выбранные значения и формирует итоговый текст из фактов. Произвольные заявления модели не отображаются.

Карточки `/api/recommend` — альтернативы. Последовательный план даёт отдельный `/api/itinerary`. Время приблизительное: не учитывает очереди, погоду, временные препятствия и движение. У крупных объектов координата может быть центром территории; подходы к сети до 120 м с каждого конца приблизительны. Доступность сейчас не подтверждается даже при наличии расписания.

`evidence[]` содержит `id`, `text`, `source_url`, `collected_at`, `kind`, `confidence` и необязательный `published_at`. `source_reported` означает сведения источника, а не независимую инспекцию. `fact_source` может быть `OpenStreetMap + official sources`. В объяснении обязательно остаётся конкретный факт, если он есть; идея занятия может быть привязана к нему, например поиск видимых камней в японском саду.

## Мини-маршрут: POST /api/itinerary

```json
{"lat":51.0890897,"lon":71.4073303,"available_minutes":120,"query":"Хочу погулять и выпить кофе","include_coffee":true}
```

Ищутся 2–3 разные остановки в ограниченном наборе кандидатов, с возвращением к исходной точке. Dijkstra работает по сохранённому графу; GPS никуда не отправляется. Сумма всех переходов + фиксированных посещений + `max(5, ceil(0.1*budget))` минут запаса должна уместиться в бюджет. Это лучший найденный вариант среди ограниченного набора, не доказанный глобальный оптимум.

Статусы: `ready`, `no_match`, `network_unavailable`. Отсутствующее соединение не заменяется прямой линией. При коротком бюджете может возвращаться проверенный `suggested_minimum_minutes`. Условия пользователя не ослабляются автоматически. `stops` содержит порядок, время прибытия/ухода, действие и доказательства; `legs` — все переходы, включая возврат. Геометрия — **[lon, lat]**. Приблизительные соединения с графом выделены длиной `connector_m`; путь не гарантирует доступность входов, переходов или отсутствие перекрытий. Безбарьерность всего маршрута не подтверждается.

Полный контракт и пример подключения: [itinerary-handoff.md](docs/itinerary-handoff.md). Граф строится отдельно от модели; отказ LLM не отключает эту функцию.

Для запросов розеток/тишины/Wi-Fi/доступности неизвестность не трактуется как совпадение. Ночной режим, аэропорт, цены и интерактивность не входят в проверенное покрытие прототипа. Неподдерживаемые условия явно отклоняются; понимание произвольного естественного языка ограничено набором правил.

## Проверки и сдача

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest -q
python test_suite.py --offline
python test_suite.py
python scripts/verify_backend.py
python scripts/verify_feature.py
```

Pytest использует синтетические фикстуры во временной папке и имитированный API модели; отдельно проверяет происхождение и воспроизводимость сохранённого реального датасета. Фикстуры не попадают в рабочие данные. Проверяются контракт, ограничения, ложные ID, ошибка/таймаут модели, отсутствие утечки координат в LLM, обновление данных и интеграция static-файлов.

`test_suite.py --offline` проверяет настоящее приложение и сохранённые данные через TestClient с отключённой моделью. `test_suite.py` проверяет работающий сервер на `http://127.0.0.1:8000`; другой адрес задаётся через `--base-url`. По умолчанию сетевой прогон не делает успешных рекомендаций, способных вызвать платный API. Для этого нужен явный `--live-llm`. Проверки охватывают каталог и метаданные, 422, неподдерживаемые условия, защищённые файлы, бюджет и возврат мини-маршрутов. При любой ошибке возвращается ненулевой код. `--output путь.json` сохраняет отчёт.

`verify_backend.py` проверяет сценарии на реальном сохранённом датасете и формирует `docs/test-scenarios.md`, `docs/verification.json`, `docs/api-example.json`, `docs/openapi.json`. Он намеренно не делает платных вызовов. Реальный RAG проверяется после добавления своего ключа.

Проверка запущенного сервера: `python scripts/check_live.py`. Проверка именно подключённой модели: `python scripts/check_live.py --require-rag` (вызов может тарифицироваться провайдером). Для кофе добавьте `--category cafe`, для сохранения отчёта — `--output docs/live-rag-cafe.json`. Памятка для участника 2: [handoff](docs/handoff.md), [готовый промпт](docs/participant-2-prompt.md), [проверенное состояние бэкенда](docs/backend-status.md), [соответствие критериям](docs/criteria-checklist.md).

## Приватность и источники

Нет базы пользователей, cookies, аналитики или хранения запросов/GPS. Для модели используются нормализованные ограничения и найденные POI; исходный текст запроса и точные координаты пользователя не отправляются. Тела запросов не логируются. Access log Uvicorn отключён; при размещении за прокси его журналы нужно настроить отдельно. Ответы API имеют `Cache-Control: no-store`.

Карта загружает сторонние тайлы: провайдер получает IP браузера и номера запрашиваемых участков карты. Это не означает передачу точного GPS в модель, но абсолютная анонимность внешних ресурсов не гарантируется. Документ отправляет внешним ресурсам только origin через `strict-origin-when-cross-origin`; API сохраняет `no-referrer`. При ошибке тайлов карта один раз запрашивает `/api/walking-map.geojson`: локальную схему реальных рёбер сохранённого графа. Она явно подписана, не показывает здания и не заменяет проверку доступности проходов. Карточки и локальный расчёт маршрута работают при доступном локальном сервере.
