# Telegis 1.2: мини-маршрут для участника 2

Файлы интерфейса не изменялись. Старый `/api/recommend` и его поля сохранены. Новая функция доступна независимо через Swagger `/docs`.

## Одна сильная фишка

**«Прогулка с возвращением и запасом»**: 2–3 разных места, настоящие связные переходы по локальному графу OSM, фиксированное время посещений, возвращение к старту и запас не меньше 5 минут / 10% бюджета. Поиск работает локально, без передачи GPS внешнему маршрутизатору или модели.

Минимальное дополнение интерфейса: кнопка «Собрать мини-маршрут», переключатель «С кофе», бюджет 60/90/120 минут. Используйте ту же выбранную стартовую точку и запрос.

```javascript
const response = await fetch('/api/itinerary', {
  method: 'POST',
  headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({
    lat: selectedLocation.lat,
    lon: selectedLocation.lon,
    available_minutes: selectedMinutes,
    query: queryText || 'Хочу погулять и выпить кофе',
    include_coffee: true
  })
});
const plan = await response.json();
```

`available_minutes`: целое 15–180. `status`:

- `ready`: показывайте `stops` по `order`, переходы `legs`, `why`, общий бюджет и запас.
- `no_match`: покажите `message`. Если есть `suggested_minimum_minutes`, предложите явно выбрать это время; не увеличивайте бюджет автоматически.
- `network_unavailable`: граф недоступен, маршрута нет. Не рисуйте прямую линию вместо него.

Ответ содержит `walking_minutes_estimate`, `visit_minutes_estimate`, `reserve_minutes`, `total_minutes_estimate`, `remaining_minutes`. Формула: **все переходы + все посещения + запас = итог**. Последний элемент `legs` возвращает к старту. В каждой остановке есть время прибытия/ухода относительно старта, действие и источники.

Геометрия `route_coordinates` и `legs[].coordinates` имеет порядок **[долгота, широта]**, как GeoJSON. Leaflet принимает [широта, долгота] — преобразуйте координаты. `connector_m` у перехода — суммарная длина приблизительных подходов к графу; каждый конец допускает не больше 120 м. Геометрия не гарантирует проход через входы, отсутствие ограждений и временных закрытий. Покажите предупреждения; при возможности выделите подходы иначе. Не называйте маршрут проверенным на месте, безбарьерным или гарантированно безопасным.

## Проверенный сценарий демо

Mega Silk Way → 120 минут → с кофе: **Аллея мира и согласия → 25-ти летие Независимости → Drinkit → старт**. Примерный итог — **107 минут: 45 переходы + 50 посещения + 12 запас**. Полный ответ: [itinerary-example.json](itinerary-example.json).

Смена на 60 минут даёт честный отказ и предлагает минимальный найденный бюджет — [itinerary-too-short.json](itinerary-too-short.json). Само предложение проверено повторным запросом. Выдача может измениться после обновления данных.

## Улучшенные обычные карточки

- `description` и `why` теперь содержат конкретные свойства места. `evidence[]` даёт источник, тип, дату сбора и дату публикации для каждого факта. В частности, статья о японском саде историческая — её дата не подтверждает нынешний доступ.
- `fact_source` теперь также может быть `OpenStreetMap + official sources`.
- `distance_m` по-прежнему **по прямой**. При `travel_basis="osm_walking_graph"` время рассчитано по сети; `route_distance_m` и `return_route_distance_m` содержат путь туда/обратно. При отсутствии графа будет `straight_line_estimate` с предупреждением.
- `time_margin_minutes` — остаток лимита для отдельной карточки; это не гарантированная задержка. В мини-маршруте отдельный запланированный запас — `reserve_minutes`.
- NU Park исключён до подтверждения доступности: официальный источник описывает будущий проект. Это видно в `/api/meta.data_quality.excluded_pending_verification`.

Проверьте геометрию, порядок остановок, итог с возвращением, короткий бюджет и отсутствие сети. Готовность бэкенда не означает, что новый элемент интерфейса уже реализован.
