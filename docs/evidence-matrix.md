# Telegis: матрица доказательств по семи критериям

Документ относится к исправлению версии, полученной из GitHub `97e7342`, в ветке `codex/verified-weather-and-demo`. Оценки ниже выставлены после реализации и проверок, а не являются целевыми баллами. Итоговые результаты конкретного прогона фиксируются в [final-evidence.json](final-evidence.json). Исходные проблемы перечислены в [head-audit.md](head-audit.md).

## Итог проверки 20 октября 2026

356 тестов pytest прошли; Node VM-проверки фронтенда прошли. Проверены 35 основных сценариев (594 проверки) и 17 климатических интеграционных сценариев. Настоящие OpenRouter RAG и Open-Meteo ответили успешно. В браузере проверены десктоп 1440×900 и мобильный экран 390×844, RU/KZ/EN, круговой маршрут, отдельный путь, отказ по неподтверждённым свойствам, недоступная погода и fallback. ## Статус источников и данных

Снимок POI содержит 134 объекта: 49 именованных и 85 детских площадок с описательными, явно неофициальными названиями. Они происходят из сохранённого ответа OSM от 19 октября 2026 года. Повторная нормализация не меняет дату получения исходных данных.

75 содержательных фактов относятся к 35 POI, из них 9 фактов получены из четырёх официальных страниц. Названия, часы, Wi-Fi и прочие поля остаются сведениями источника. Возраст детей, исправность оборудования, тишина, розетки и доступность всего маршрута не подтверждены. Источник и дата получения доступны в данных и API.

Open-Meteo предоставляет модельные погодные данные для фиксированной точки EXPO. `valid_at` обозначает время, к которому относится модельное значение, `fetched_at` — время получения ответа нашим сервером. Значение `status: "live"` не означает показание ближайшей метеостанции. Описание API: [Open-Meteo](https://open-meteo.com/en/docs).

## Артефакты текущей проверки

- [Реальный вызов RAG](live-rag-verification.json): 20 октября 2026, 17:46 UTC; `mode: "rag"`, две рекомендации, 2,28 секунды. Это измерение одного запроса, не обещание задержки и доступности модели.
- [Проверка PDF](../presentation/pdf-verification.md): шесть страниц после нового экспорта, каждая отрендерена и визуально просмотрена. Проверка ошибки экспортера подтвердила ненулевой код и сохранение прежнего файла.
- [OpenAPI](openapi.json) экспортирован из текущего приложения: запросы рекомендаций, мини-маршрута и пути к точке включают `climate_shield` и `locale`; погодный endpoint представлен отдельно.
- [Итоговый протокол](final-evidence.json) содержит полный состав завершённых тестов и браузерных сценариев, включая непроверенные условия. Числа старых отчётов к этому прогону не прибавляются.

## Правила интерпретации результатов

- Тесты со стабом погодного API подтверждают обработку заданных условий, но не доказывают доступность Open-Meteo в момент демонстрации.
- Вызов настоящей модели считается успешным только при `mode: "rag"` конкретного ответа. Наличие ключа или `llm_configured: true` недостаточно.
- Синтетическая погода и записанные ответы показываются только с явной пометкой деморежима. Сбой сети не должен незаметно включать демонстрационные данные.
- Статус «готово к сдаче» подтвержден загруженным видеодемо: https://youtu.be/ZLQ37BQ5e6I.
- Исторические количества тестов и старые самооценки сохранены в архивных отчётах. Они не являются текущей оценкой качества.
