# Передача участнику 2

**Версия 1.2:** новая функция и расширенные карточки описаны в [itinerary-handoff.md](itinerary-handoff.md). Обычные поля сохранены. `fact_source` теперь может включать официальные источники, а время при наличии графа считается по пешеходным путям. Старые пояснения ниже о версии 1.1 читайте вместе с этим дополнением.

Скопируйте свои папки `static/` и `presentation/` в корень `Telegis`, рядом с `app/`. Бэкенд не изменял эти папки.

Сервер: `http://127.0.0.1:8000`. Swagger: `/docs`. Ресурсы интерфейса — `/static/...`. API и UI находятся на одном origin; отдельный сервер для HTML не нужен.

- `GET /api/locations` — реальные начальные точки. Не зашивайте координаты.
- `POST /api/recommend` — согласованный контракт из промпта сохранён.
- `GET /api/meta` — фактическое число POI, атрибуция, дата, ограничения; удобно для экрана «О данных».
- `GET /api/health` — наличие датасета и настроек модели. `llm_configured` не означает успешный вызов.

Фактический пример запроса/ответа: [api-example.json](api-example.json). Полная схема: [openapi.json](openapi.json). Результаты приёмочных сценариев: [test-scenarios.md](test-scenarios.md).

В `recommendations` может быть 0–3 элемента. Пустая выдача — не ошибка сети: покажите `message`. Для всех ответов выводите `message`, особенно при `mode="fallback"`. Режим `rag` появляется только после успешного проверенного ответа внешней модели.

Временные карточки — альтернативы, не маршрут. Общий бюджет включает возвращение: `2 × walk_minutes_estimate + visit_minutes_estimate`. Расстояние всегда по прямой. Отмечайте время как приблизительное.

`opening_hours` может быть null. Не выводите «открыто сейчас». Все `warnings` необходимо показывать. Подпись `collected_at` — «Данные собраны», а не «Проверено».

Дополнения версии 1.1, совместимые с прежними полями:

- Название API и продукта — **Telegis**.
- `used_context.effective_minutes` и `max_distance_m` — фактически применённые лимиты; `required_features` и `excluded_categories` — учтённые условия. Показывайте их, особенно когда текст уточняет форму.
- Карточка содержит `description`, `phone`, `website` (последние два могут быть null). Телефон выводите текстом; для сайта — HTTP/HTTPS-ссылка «Уточнить на сайте». Это контакты из OSM, не подтверждение доступности.
- `fact_source="OpenStreetMap"` и `activity_source="suggested_idea"` явно отделяют факты от предложенного занятия.
- `/api/meta.data_quality` содержит фактическую полноту часов, контактов и подтверждённых свойств. Нулевые подтверждения означают пробел в данных, не отсутствие услуги в городе.
- `/api/health.llm_last_status` — результат последней попытки модели в процессе; `not_checked` после запуска нормально. Для конкретной выдачи смотрите `mode`.

Оба основных сценария проверены с настоящим OpenRouter: [прогулка](live-rag-walk.json), [кофе](live-rag-cafe.json). Сохраните видимый резервный режим: доступность внешнего API может меняться.

Показывайте атрибуцию © OpenStreetMap contributors с ссылкой https://www.openstreetmap.org/copyright . Для `source_url` используйте безопасную внешнюю ссылку. Строки API вставляйте через `textContent`.

После подключения проверить:

1. Mega Silk Way → прогулка → 60 минут: несколько реальных вариантов.
2. 20 минут: выдача меняется; при отсутствии подходящих мест видно объяснение.
3. Кофе → 60 минут: карточки кафе.
4. «Тихое кафе с розеткой»: нет выдуманных подтверждений.
5. `.env` не настроен/модель недоступна: виден fallback.
6. Отказ от GPS: выбор точки из списка продолжает работать.

Реальный HTTP-smoke: `python scripts/check_live.py`.
После настройки ключа и перезапуска: `python scripts/check_live.py --require-rag`.
Последняя команда завершается ошибкой, если вместо реального RAG получен fallback.

Не публикуйте `.env`. В передаваемый архив ключ не включён.
